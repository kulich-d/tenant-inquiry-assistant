# Plan — shared "emailed" marks (replace the localStorage mock)

## Goal

When Sarah ticks an invoice as emailed, Jonas sees it on his own computer — so they stop emailing the same tenant twice.

## Rules

- One mark per invoice: who (`Sarah` / `Jonas`) and when. No history: unticking deletes the mark.
- **First mark wins.** If Jonas ticks an invoice Sarah already marked, Sarah's mark stays and Jonas is told "Sarah already marked …". This is the double-email case.
- Anyone on the team can untick any mark.
- Who is acting still comes from the "You:" switcher (no auth in v1); the server only accepts known team members.

## Design

- **DB**: SQLite file via Drizzle (`@libsql/client`, no native build). `DATABASE_URL`, default `file:data/late-rent.db` (git-ignored).
  Table `contacts`: `invoice_id` (PK), `sent_by`, `sent_at`. Migrations generated by drizzle-kit, applied automatically on first use, so `npm run dev` just works.
- **Repository** (`src/server/contacts.ts`): `listContacts`, `markEmailed` (insert, on conflict do nothing → return the stored rows), `unmarkEmailed`. Takes the db as a parameter → tested against in-memory SQLite.
- **Server Actions** (`src/app/actions.ts`): `markEmailedAction({ invoiceIds, sentBy })`, `unmarkEmailedAction({ invoiceId })`. zod-validated input, return a typed result (`ok` + stored contacts / `error`), never throw to the UI. `refresh()` after writing.
- **Page**: the ledger (invoices + payments) stays static and cached; contacts are read fresh per request inside `<Suspense>`.
- **UI**:
  - `useOptimistic`: the tick shows at once, rolls back with an error message if the save fails.
  - "Already marked by …" notice when someone else got there first.
  - "Mark all emailed" on the tenant row — one email usually covers every overdue invoice.
  - Auto-refresh: `router.refresh()` when the tab regains focus and every 30 s, so Jonas sees Sarah's marks without reloading.

Removed: `mocks/contactsStore.ts`, `mocks/seedContacts.ts`, `ContactsStoreContext`.

## Tests

- Repository (in-memory SQLite): mark, unmark, first mark wins, marking several invoices at once, list.
- Actions: invalid input (unknown user, empty list) rejected without touching the DB.
- UI (actions mocked): tick shows at once and calls the action; failed save rolls back and shows an error; "already marked by Jonas" notice; "Mark all emailed".

## Steps

1. Drizzle + libsql, schema, migration, db client
2. Repository + tests
3. Server Actions + tests
4. Page: cached ledger + fresh contacts in Suspense
5. UI: optimistic ticks, notices, mark all, auto-refresh; remove the mock
6. UI tests; check with Sarah and Jonas in two browser tabs
